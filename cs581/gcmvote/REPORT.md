# A reference-free vote model for GCM edge support

AI-assisted (Claude), exploration code for CS581 project.

Exploration pilot, CS581 (UIUC), Fall 2026. All experiments are merge-only. MAGUS's own 25 L-INS-i subset
alignments and its 10 L-INS-i backbones (200 sequences each) are fixed, and only the GCM graph changes. Every
variant is paired with `magus`, which is MAGUS's own graph run through the same driver (`code/vote.py`):
- it reproduces the cached MAGUS score (BBA0101 29.19 %);
- it gives the same edge count as gcmgen's `edge_support.py` (1,087,771 on BBA0101).

Where to find things:
- Pre-registration: `PREREG.md`, pushed before any variant was scored, with the selection outcome appended at 03:07.
- All tables: `results/tables.md`, generated by `code/summarize.py`.
- Trees: `results/trees.md`, from `code/pool_trees.py`.
- Raw rows: `results/raw/`.

## TL;DR

1. **The model.** For every cross-subset edge, two counts are taken:
   - k = how many backbones vote for it (support);
   - n = how many backbones *could* vote for it (exposure: the backbone holds a residue in both columns).

   A zero-truncated two-component mixture (true / false edges) is fitted per run by EM, with no reference. Keeping
   edges with posterior > 0.5 is a reference-free filter.
   - The selected variant is `hard-bb`, the beta-binomial mixture. It was chosen on training by the
     pre-registered rule.
   - Training means: `hard-bb` −1.29, binomial `hard` −1.20, `es4` −1.11.
2. **Primary endpoint (held-out, 14 replicates).** `hard-bb` vs MAGUS: **−1.33 error points** (W/T/L 8/2/4,
   Wilcoxon p = 0.091).
   - Proteins: **−4.63** (4/0/0). DNA/RNA: **−0.01** (4/2/4).
   - Against the hand-picked `es4` on the same sets: −0.30 (5/5/4, p = 0.72). Proteins −1.15 (BAliBASE −2.33 on
     both sets, AliSim ≈ 0); DNA/RNA +0.04.
   - The pre-registered verdict rule ("not worse than es4 by > 0.1 overall, no data type worse by > 0.25") is met
     on held-out.
   - On training, however, DNA/RNA is +0.26 worse than es4 (1000M2 +0.66, 1000L1 +0.45, 1000L2 +0.56).
3. **Which cutoff does the model choose?** Not 4. At full exposure (n = 10) the binomial model keeps k ≥ 6 to 8
   (median 7). The beta-binomial model keeps k ≥ 5 to 9.
   - The cutoff falls with exposure: k ≥ 4 at n = 5 on every data set. This is the one thing a fixed k/B rule
     cannot do.
   - With B = 5 backbones the model keeps 4 of 5. The fraction it chooses rises as B falls (0.6–0.7 at B = 10,
     0.8 at B = 5), so a fixed fraction k/B is not what the data want either.
4. **Calibration is good at the extremes and poor in the middle.**
   - Pooled over 23 replicates: posterior < 0.1 → 4 % of edges true (28 M edges); posterior > 0.9 → 91 %
     (binomial) / 95 % (beta-binomial).
   - Between 0.5 and 0.9 the posteriors overstate precision: true precision is 0.35–0.57.
   - The binomial mixture fits badly everywhere (G 6·10⁴ to 6·10⁵ on ~55 cells). The beta-binomial fits 3–40×
     better (lower BIC on every replicate), because false edges' votes are correlated, not independent coin flips.
5. **Soft weighting does not work.** Multiplying edge weights by the posterior keeps the junk edges' topology:
   - `soft`: held-out −0.37; `soft4`: −0.78; on SIMHIGH_R1 `soft` is +1.01.
   - MCL needs edges *gone*, not down-weighted.
6. **Trees.** Pooled FastTree nRF on 20 SIMHIGH datasets (R1–R2 from this branch, R3–R20 from the helpers):
   none of the variants improves trees significantly.
   - `hard-bb`: −0.37 (11/3/6, p = 0.20).
   - `es4`: −0.23 (p = 0.18).
   - The tree variant `hard+mask`: −0.05 (n = 17).
   - The true alignment: −3.14. The vote recovers about a tenth of the gap to the true alignment.
7. **Verdict.** The vote model is a *principled, reference-free* replacement for the hand-picked k = 4. On
   held-out data it is at least as good as es4 (better on BAliBASE by ~2.3 points, equal on DNA/RNA). It is also
   more aggressive than es4, which costs some DNA recall on the hard ROSE training sets. It does not help trees.

## 1. Model

For each MAGUS run, the graph is built exactly as MAGUS builds it: per backbone b, the column-by-node count
matrix A_b, and the graph Σ_b A_bᵀA_b (as in `gcmx.fastgraph`). For every cross-subset edge (a in subset A,
b in subset B), three quantities are recorded:
- weight = MAGUS's weight;
- k = #{b : (A_bᵀA_b)[a, b] > 0}, the support;
- n = #{b : backbone b holds a residue in node a and in node b}, the exposure. It is computed with per-node
  coverage bitmasks; k ≤ n always.

Only edges with k ≥ 1 exist, so both components are **zero-truncated**: P(k | n) / (1 − P(0 | n)).

Fitting:
- The EM runs on the aggregated (k, n) table (≤ 55 cells for B = 10), so a fit takes about a second.
- M-steps: bounded scalar search (binomial p) or L-BFGS (beta-binomial mean and concentration).
- Component 1 is the one with the larger mean.
- The posterior w = P(true | k, n) is per cell.

Variants (all pre-declared):

| name | rule |
|---|---|
| `hard` / `hard-bb` | delete cross-subset edges with w ≤ 0.5 |
| `soft` / `soft-bb` / `softγ` | weight × w^γ (γ = 1, 2, 4; γ = 4 is best on training); weights ×1000 and rounded, since MCL is scale-invariant |
| `es4`, `fracF` | delete edges with k < 4 / k < ⌈F·B⌉ |
| `hard+mask`, `magus+mask` | tree variant: remove final columns whose cross-subset evidence (unfiltered edges whose two nodes ended in the same column) has weight-weighted mean posterior < 0.5 |

Fitted values:
- Binomial: p1 = 0.86–1.00, p0 = 0.08–0.23, π = 0.08–0.89. π is large on easy sets (1000M4 0.89, BBA0039 0.60)
  and small on hard ones (1000L3 0.08).

## 3. Calibration (reference used; diagnostic only)

Precision of an edge follows gcmgen's definition: the fraction of its backbone residue-pair units that are true
homologies. "Edge precision" = the share of edges whose units are mostly true. Pooled over all 23 calibrated
replicates (`code/calib.py`):

| posterior bin | binomial: edges | mean w | edge precision | beta-binomial: edges | mean w | edge precision |
|---|---|---|---|---|---|---|
| 0.0–0.1 | 27,915,347 | 0.00 | 0.04 | 26,121,180 | 0.02 | 0.04 |
| 0.1–0.2 | 204,851 | 0.16 | 0.21 | 1,272,331 | 0.14 | 0.13 |
| 0.2–0.3 | 82,336 | 0.26 | 0.29 | 483,680 | 0.25 | 0.20 |
| 0.3–0.4 | 11,503 | 0.36 | 0.28 | 204,542 | 0.34 | 0.25 |
| 0.4–0.5 | 70,013 | 0.44 | 0.33 | 260,433 | 0.45 | 0.28 |
| 0.5–0.6 | 40,842 | 0.57 | 0.36 | 167,729 | 0.55 | 0.42 |
| 0.6–0.7 | 18,785 | 0.65 | 0.35 | 136,652 | 0.65 | 0.36 |
| 0.7–0.8 | 70,382 | 0.73 | 0.35 | 165,936 | 0.75 | 0.48 |
| 0.8–0.9 | 144,871 | 0.85 | 0.37 | 223,125 | 0.85 | 0.57 |
| 0.9–1.0 | 5,781,360 | 1.00 | 0.91 | 5,304,682 | 0.99 | 0.95 |

What the table shows:
- The hard filter keeps 95–99 % of the true residue-pair units. It is a high-recall filter.
- Per-replicate expected calibration error (edge level): 0.02–0.15 binomial, 0.01–0.11 beta-binomial.
  - Best on ROSE DNA (≤ 0.04).
  - Worst on the hard BAliBASE sets. On BBA0101 even edges with k = 9 of 10 are only 31 % true at edge level.
- The middle bins are overconfident, and that is a model misspecification: the binomial assumes true edges'
  votes are independent with a common p1, but true edges near indel-rich regions are systematically
  under-voted, and false edges in a misaligned region are voted for together.
- The beta-binomial's extra dispersion is the right direction (better G, BIC and ECE), but it is still not
  calibrated between 0.5 and 0.9.

How the gain splits by error type:
- On proteins the vote's extra gain over es4 is a **precision** gain. `hard` held-out proteins: ΔSPFN / ΔSPFP

## 7. Verdict

- **Does the model give a principled, reference-free cutoff?** Yes. Its effective cutoff is chosen per run and
  per exposure.
  - On held-out data it matches or beats the hand-picked k = 4 everywhere except a few hard ROSE sets
    (worst +0.30).
  - Its held-out mean is −1.33 vs MAGUS (p = 0.09) and −0.30 vs es4 (not significant).
- **It is not "the right k, found automatically".** The mixture separates junk edges (k ≈ 1–3) from the k = n
  mass, and the posterior boundary lands at 0.6–0.8 of the exposure, stricter than 4/10.
  - That suits proteins, where the extra precision helps.
  - It is slightly too strict for recall-limited DNA.
  - Calibration is good only at the extremes.
- **Number of backbones.** A fixed fraction k/B does not transfer across B: the model wants 4/5 at B = 5 and
  6–7/10 at B = 10 (see §5).
- **Trees.** No variant (es4, hard, hard-bb, the masked tree variant) improves FastTree trees significantly on
  SIMHIGH, consistent with gcmtrees.

**Honest bottom line.** Use `hard-bb` instead of a hand-picked k if one wants a filter without a magic constant.
Expect about +2 points on hard BAliBASE-like proteins, the same as es4 on simulated proteins, roughly neutral
DNA/RNA (−0.01 held-out, but up to +1.0 on the hardest ROSE training set), and nothing for trees.

## 8. What a 4-week project would do

1. **Fix the misspecification, not the threshold.**
   - Model false votes as correlated within an alignment region: a column-level random effect, or a latent class
     per (subset-pair, region).
   - Use features beyond (k, n): residue-pair count per voting backbone, gap fraction of the columns, whether the
     edge competes with a stronger edge from the same column.
   - Fit it as a reference-free EM or a small discriminative model trained on simulated data and checked on
     BAliBASE.
2. **Decision rule matched to MCL's cost.** Choose the threshold that maximises the expected SP score of the
   merged alignment (asymmetric loss: a deleted true edge costs recall only when no alternative path exists),
   not posterior > 0.5. This is where the DNA losses come from.
3. **More draws and replicates.** One MAGUS draw per dataset is the main noise source. Five draws × 24 datasets
   would give real p-values on held-out (current n = 14, p = 0.09).
4. **Backbone design.** Use the model's exposure to choose *which* backbones to add: backbones that raise n for
   low-exposure edges rather than 10 more random ones. Also test backbone size 100.
5. **Trees.** Since SP gains do not transfer to FastTree, test whether masking by posterior *before* tree
   inference helps IQ-TREE (+G) rather than FastTree, and measure on columns that matter (variable sites).
